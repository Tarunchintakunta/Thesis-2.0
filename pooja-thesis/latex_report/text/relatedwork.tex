\section{Related Work}
\label{sec:rw}

Kubernetes' built-in Horizontal Pod Autoscaler (HPA) and event-driven autoscalers like KEDA are both reactive: they scale only after a metric threshold is already crossed, which under bursty workloads leads to either SLA-violating under-provisioning or costly over-provisioning.

\subsection{Baseline: Proactive Autoscaling with Deep Q-Networks}
The baseline for this project is Wanigasooriya \& Ekanayake \cite{Wanigasooriya26}, ``NimbusGuard: A Novel Framework for Proactive Kubernetes Autoscaling Using Deep Q-Networks'' (IEEE ICOIN 2026). NimbusGuard combines a Deep Q-Network scaling agent with an LSTM workload forecaster, evaluated against reactive HPA and event-driven KEDA on a real KinD Kubernetes testbed under a phased load pattern (ramp-up, sustained load, peak load, cooldown). Their results show NimbusGuard reduces the metric they care most about -- responsiveness -- outperforming both reactive baselines.

\subsection{The Gap This Project Targets}
The same results table exposes the cost of that responsiveness. NimbusGuard runs with the highest average replica count (5.44 vs. 3.05 for HPA and 2.93 for KEDA) and double the total scaling events of either reactive baseline (8 vs. 4). The paper states this directly: ``NimbusGuard was the most agile and least stable system... these findings highlight a fundamental trade-off: the proactive, performance-focused scaling of NimbusGuard versus the reactive, cost-efficient stability of traditional autoscalers.'' Their own future-work section gestures at addressing this (expanding the action space, hybridising with Vertical Pod Autoscaling) but does not build or evaluate a fix.

\subsection{Smoothing and Hysteresis in Autoscaling}
Damping noisy scaling signals with smoothing and cooldown windows is a long-established idea in autoscaler design generally (Kubernetes HPA itself has a stabilization-window option), but it is not what NimbusGuard's own DQN+LSTM pipeline does -- their agent acts on every raw forecast. This project reproduces the aggressive, unfiltered proactive-scaling trade-off NimbusGuard reports, then applies exactly this kind of smoothing/hysteresis rule on top of the same underlying predictive signal, to test whether it recovers stability without giving back the SLA benefit of forecasting in the first place.

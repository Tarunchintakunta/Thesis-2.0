\section{Conclusion and Future Work}
\label{sec:Conclusion}
%% ==================

Formal CA2 asks whether PAKS (LSTM workload prediction + adaptive Kubernetes scaling) improves resource management versus reactive HPA on Google / Alibaba traces, on a Kubernetes cluster hosted on AWS, under MAE/RMSE, utilisation, latency, throughput, cost, and SLA. This artefact does \textbf{not} yet answer that question on a live cluster.

This pass: (i)~states HPA as the binding baseline and quarantines the NimbusGuard MLP simulator as proxy; (ii)~ingests a public GCT v1 (2010) slice with SHA1 provenance and trains a NumPy LSTM (TensorFlow fail-closed); (iii)~emits dry-run Kubernetes Scale patches versus an HPA v2 schema; (iv)~wires the formal metric columns with TRACE vs SIMULATED tags. GCT 2011/2019 and Alibaba remain absent. AWS was not deployed.

\textbf{Blockers (not complete):}
\begin{itemize}
  \item Ingest GCT 2011/2019 and/or Alibaba \texttt{machine\_usage} and re-run LSTM MAE/RMSE on those traces.
  \item Apply Scale patches on kind/minikube or an AWS Kubernetes cluster and measure kubelet scaling latency, request latency, and CloudWatch/billing cost (live, not simulated).
  \item Host the experimental environment on AWS EC2 with S3-backed datasets as specified.
  \item Soft: add the missing Gantt figure from the formal CA2 week grid; optional TensorFlow runtime on Python 3.10--3.12.
\end{itemize}

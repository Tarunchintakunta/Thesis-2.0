\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

Serverless computing, particularly AWS Lambda, provides event-driven, auto-scaled function execution but introduces cold-start latency—initialization delays ranging from 100 milliseconds to several seconds that degrade user-perceived performance. This research systematically investigates developer-adjustable controls for cold-start mitigation: runtime language selection (Python 3.12, Node.js 20, Java 21), deployment package optimization (bloated vs. minimal dependencies), memory allocation (128–3008 MB), and low-frequency EventBridge warming (5-minute schedule).

Extending Bluemke and Zdanowski's (2025) Lambda configuration analysis, this study isolates \textit{Init Duration} (cold-start initialization overhead) from total execution time, enabling precise identification of where latency originates. Four pre-registered hypotheses test runtime differences (H1), package-size effects per runtime (H2), warming impact on cold-start frequency (H3), and memory allocation effects (H4, exploratory).

The experimental artefact comprises six Lambda function variants (3 runtimes × 2 package sizes) implementing identical SHA-256 computation, Infrastructure-as-Code (AWS SAM template), data collection pipeline (invoke → CloudWatch Logs → parse → cost model → statistical analysis), and 100+ pytest tests. Proxy benchmarks (local process initialization on GitHub Actions CI runner) validate hypothesis directions: Python default configuration (21 MB with boto3/requests/sympy) median init proxy 2383.7 ms vs. optimised (604 B, stdlib only) 20.9 ms—a 2362.8 ms reduction (rank-biserial = 1.00, p = 4.3e-14). Similar effects observed for Node.js (293.2 ms reduction) and Java (185.9 ms reduction). Minimal packages show similar baseline init proxy times across runtimes (within 16 ms), suggesting dependency bloat dominates runtime choice for initialization cost.

Results are expressed as a decision matrix: milliseconds saved per dollar per 1,000 invocations, enabling practitioners to select optimizations matching latency and budget constraints. Package pruning yields near-infinite ROI (negligible cost increase, substantial latency reduction), placing it in the "ADOPT" band. The study provides a reproducible artefact, rigorous pre-registered methodology (Shapiro-Wilk normality checks, Holm-Bonferroni correction, mandatory effect sizes), and explicit data provenance (proxy benchmarks: real; mock data: synthetic for pipeline validation; live Lambda: awaiting execution).

\textbf{Keywords:} Serverless computing, AWS Lambda, cold-start latency, Init Duration isolation, runtime comparison, package optimization, performance-cost trade-offs, reproducible research

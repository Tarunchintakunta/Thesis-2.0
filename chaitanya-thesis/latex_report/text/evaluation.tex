\textit{Init Duration} cells were collected under a Free-Tier \textbf{lite} sample

directional only. Point-estimate ROI / ADOPT-candidate bands use the measured cost model
on live REPORT billed milliseconds; they are \textbf{not} Holm-confirmed decision bands.

\subsection{ROI / ADOPT point estimates (measured billed ms)}

Costs from \texttt{scripts/cost\_model.py} on live REPORT billed duration (arch
\texttt{arm64}, prices in \texttt{configs/pricing.yaml}). All-cold cost per 1{,}000 for
package prune (lite $n{=}12$):

\begin{itemize}
    \item Python default $\rightarrow$ optimised: median Init saving $3267.6$\,ms;
      $\Delta$cost/1k $\approx -\$0.041$ (ADOPT-candidate \emph{lite point estimate}).
    \item Node.js default $\rightarrow$ optimised: $860.3$\,ms; $\Delta$cost/1k
      $\approx -\$0.012$ (ADOPT-candidate lite).
    \item Java default $\rightarrow$ optimised: $353.9$\,ms; $\Delta$cost/1k
      $\approx -\$0.004$ (ADOPT-candidate lite).
    \item Memory $128{\rightarrow}1024$\,MB (Python optimised): Init median $\Delta$
      $14.8$\,ms; HOLD-lite.
    \item H3 warming: cold-fraction drop $0.20$; $\Delta$cost/1k $\approx +\$4{\times}10^{-5}$
      (ADOPT-candidate lite on thresholds; $n{=}10$/arm).
\end{itemize}

These bands apply practical thresholds from \texttt{configs/analysis\_plan.yaml} only.
They are \textbf{not} substitutes for the pre-registered Holm family.
Lite Holm results: H1/H2 \textbf{reject}; H3 \textbf{fail to reject} ($n_{\mathrm{blocks}}=3$).
Warming therefore stays \texttt{avoid} on the Holm decision matrix even though the
point-estimate cold-rate drop is $0.20$.

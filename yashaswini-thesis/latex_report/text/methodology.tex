\chapter{Research Methodology}

\section{Research Design Overview}

This research employs an experimental design evaluating a rule-based fault detection and localisation system against published deep learning baselines and on benchmark data. The methodology combines controlled fault injection experiments, offline benchmark evaluation, and overhead measurement to position the proposed approach on the accuracy-overhead Pareto frontier.

\section{Three-Leg Evaluation Protocol}

A key methodological challenge is that trained deep learning methods and untrained rule-based methods cannot operate on identical inputs: the former require labeled training corpora that the latter explicitly avoid. To enable fair comparison, we establish a three-leg protocol:

\subsection{Leg 1: Published Ceiling (Citation Only)}

\textbf{Purpose:} Establish the accuracy ceiling achievable under ideal labeled-data conditions.

\textbf{Method:} Report Xing et al.'s (2025) published results (detection F1 = 93.8\%, accuracy = 95.4\%, localisation precision = 87.6\%) as the reference ceiling. These figures represent semi-supervised evaluation on the authors' own dataset with extensive training data.

\textbf{Not a same-rig comparison:} Xing et al.'s system runs on their infrastructure with their data. We cite their results to contextualise our rule-based performance but do not claim direct competition.

\subsection{Leg 2: Like-for-Like on RCAEval (Common Data)}

\textbf{Purpose:} Direct comparison of detection/localisation accuracy on identical cases.

\textbf{Dataset:} RCAEval benchmark \citep{pham2025rcaeval} provides 735 labeled failure cases across three microservice systems (Online Boutique, Sock Shop, Train Ticket). We use the RE2-OB (Online Boutique) subset: 90 cases covering 6 fault types × 5 services × 3 repetitions.

\textbf{Baseline methods:} We compare the rule-based approach against four reproducible RCAEval baselines:
\begin{itemize}
    \item \textbf{BARO} \citep{pham2024baro}: Multivariate Bayesian online change point detection
    \item \textbf{CIRCA} \citep{li2022circa}: Causal inference with intervention recognition
    \item \textbf{TraceRCA} \citep{li2021tracerca}: Spectrum-based localisation from trace analysis
    \item \textbf{CausalRCA} \citep{xin2023causalrca}: GNN + PageRank root cause scoring (attempted; committed $n{=}4$ only and fixed-order flagged --- quarantined, not a peer)
\end{itemize}

\textbf{Evaluation metrics:}
\begin{itemize}
    \item \textbf{Detection:} Precision, Recall, F1-score
    \item \textbf{Localisation:} Top-1, Top-3, Mean Rank, AC@k (accuracy at rank k), Avg@k (average rank at k)
\end{itemize}

\textbf{Adaptation:} The rule-based detector and ranker are adapted to RCAEval's telemetry schema (10-second buckets, 600-second observation windows) but use the same threshold logic and ranking formula as the AWS implementation.

\subsection{Leg 3: Overhead on Live AWS (or Simulated Equivalent)}

\textbf{Purpose:} Measure monitoring cost in telemetry volume, latency, and dollars.

\textbf{Method:} Deploy the AWS serverless artefact and run controlled fault injection campaigns under two sampling conditions:
\begin{itemize}
    \item \textbf{Full tracing:} X-Ray sampling rate = 100\%, all CloudWatch logs enabled
    \item \textbf{Policy tracing:} X-Ray sampling rate = 5\% (fixed), ERROR-level CloudWatch logs only
\end{itemize}

\textbf{Overhead metrics:}
\begin{itemize}
    \item \textbf{Telemetry volume:} Log bytes + trace bytes per 1000 requests
    \item \textbf{Added latency:} End-to-end P50 and P95 latency, tracing ON minus tracing OFF
    \item \textbf{Estimated cost:} Volume × AWS pricing (CloudWatch: \$0.50/GB ingested; X-Ray: \$5/million traces recorded) per million requests
\end{itemize}

\textbf{Asymmetry:} Deep learning baselines run offline on stored telemetry and cannot be instrumented in the live system. We report rule-based overhead in absolute terms and lower-bound learned method overhead from their published input requirements.

\textbf{Simulated alternative:} When live AWS deployment is infeasible (cost, credentials, time), we use simulated telemetry (`sim/telemetry.py`) that mimics CloudWatch metric patterns and X-Ray trace structures. Simulated results verify pipeline correctness but are \textit{not} valid for overhead claims.

\section{Independent and Dependent Variables}

\subsection{Independent Variables (Rig Experiments)}

\begin{itemize}
    \item \textbf{Fault type:} \{dependency\_failure, timeout, throttling, elevated\_latency\}
    \item \textbf{Load level:} \{steady (2 RPS), peak (10 RPS)\}
    \item \textbf{Target service:} \{inventory, payments, notifications\} (orders-api is entry point, not targeted)
\end{itemize}

\subsection{Dependent Variables}

\subsubsection{Detection Performance}
\begin{itemize}
    \item Precision: TP / (TP + FP)
    \item Recall: TP / (TP + FN)
    \item F1-score: 2 × (Precision × Recall) / (Precision + Recall)
    \item Detection delay: Time from fault injection start to first alarm (median, P95)
\end{itemize}

\subsubsection{Localisation Performance}
\begin{itemize}
    \item Top-1 accuracy: Proportion of cases where injected service ranks first
    \item Top-3 accuracy: Proportion of cases where injected service ranks $\leq$3
    \item Mean rank: Average rank of the injected service
    \item End-to-end Top-3: Top-3 accuracy including missed detections (treated as rank $>$3)
\end{itemize}

\subsubsection{Monitoring Overhead}
\begin{itemize}
    \item Log volume: Bytes ingested per 1000 requests
    \item Trace volume: Spans recorded per 1000 requests
    \item Latency delta: P50 and P95 end-to-end latency increase with tracing enabled
    \item Cost estimate: Dollars per million requests at AWS list prices
\end{itemize}

\section{Replication and Statistical Power}

\subsection{Rig Experiments}
\begin{itemize}
    \item \textbf{Unit of analysis:} One fault injection (60 seconds ON, 300 seconds recovery)
    \item \textbf{Replication:} 60 injections per fault type per load level, evenly distributed over the three target services
    \item \textbf{Total injections:} 4 fault types × 2 load levels × 60 = 480 injections
    \item \textbf{Control periods:} 60-minute fault-free period before each campaign establishes false-positive baseline
\end{itemize}

\textbf{Power analysis:} Using two-proportion z-test with $\alpha = 0.05$, $\beta = 0.2$ (80\% power), detecting a 10 percentage point F1 difference requires $n \approx 199$ per group. With 240 injections per load level (pooled across fault types), the design achieves adequate power for the primary hypothesis. Per-fault-type comparisons (n = 60) are descriptive rather than inferential.

\subsection{RCAEval Benchmark}
\begin{itemize}
    \item \textbf{Unit of analysis:} One RCAEval failure case (600 seconds observation window)
    \item \textbf{Sample:} RE2-OB subset, 90 cases total
    \item \textbf{Baseline methods:} BARO, CIRCA, TraceRCA on identical $n{=}90$ cases; CausalRCA quarantined ($n{=}4$, fixed-order)
\end{itemize}

No replication is needed; each case is deterministic given the RCAEval telemetry.

\section{Hypotheses and Statistical Tests}

All tests use $\alpha = 0.05$ with Holm-Bonferroni correction within each hypothesis family.

\subsection{H1: Detection Accuracy (Leg 2)}

\textbf{Null hypothesis:} F1-score does not differ between the rule-based approach and RCAEval baselines on common data.

\textbf{Alternative:} Rule-based F1 differs by $>$10 percentage points from the strongest baseline.

\textbf{Test:} Paired permutation test on per-case (TP, FP, FN) outcomes + paired bootstrap confidence interval (95\%) for F1 gap. If CI is entirely below 10pp, hypothesis is supported; if entirely above, refuted; else inconclusive.

\subsection{H2: Localisation Accuracy (Leg 2)}

\textbf{Null hypothesis:} Top-k accuracy does not differ between rule-based and baseline methods.

\textbf{Test:}
\begin{itemize}
    \item \textbf{Top-1, Top-3:} McNemar's exact test (paired binary outcomes)
    \item \textbf{Mean rank:} Shapiro-Wilk normality test, then Welch's t-test (Cohen's d effect size) if normal, else Mann-Whitney U (rank-biserial effect size)
\end{itemize}

\textbf{Family:} 3 tests × 4 baselines = 12 comparisons, Holm-Bonferroni corrected.

\subsection{H3: Overhead (Leg 3)}

\textbf{Null hypothesis:} X-Ray tracing does not change end-to-end latency.

\textbf{Alternative:} Tracing adds measurable latency at P50 or P95.

\textbf{Test:} Shapiro-Wilk normality test on latency distributions, then Welch's t-test if normal, else Mann-Whitney U. Report medians, P95, and effect sizes.

\subsection{H4: Telemetry Volume Reduction}

\textbf{Claim:} Policy sampling (5\% X-Ray) reduces telemetry volume by $\geq$50\% vs full tracing (100\%).

\textbf{Test:} Deterministic calculation from recorded trace counts: $1 - (\text{volume}_{\text{policy}} / \text{volume}_{\text{full}}) \geq 0.5$.

\section{Pre-Committed Expectations and Decision Rules}

To avoid post-hoc hypothesis adjustment, we state expectations before evaluation:

\begin{enumerate}
    \item \textbf{Detection accuracy:} Rule-based F1 within 10pp of strongest RCAEval baseline
    \begin{itemize}
        \item \textit{Decision rule:} 95\% CI of F1 gap entirely below 10pp = supported
    \end{itemize}
    
    \item \textbf{Localisation penalty:} Rule-based Top-3 concedes $>$10pp vs deep learning methods
    \begin{itemize}
        \item \textit{Decision rule:} Paired bootstrap CI of (Best Baseline Top-3 - Rule Top-3): lower bound $>$10pp = supported
    \end{itemize}
    
    \item \textbf{Overhead reduction:} Policy sampling cuts telemetry volume by $\geq$50\%
    \begin{itemize}
        \item \textit{Decision rule:} Direct calculation from trace counts
    \end{itemize}
    
    \item \textbf{Competitiveness:} F1 within 10pp of strongest baseline \textit{and} volume $\geq$50\% reduced
    \begin{itemize}
        \item \textit{Decision rule:} Both conditions must hold
    \end{itemize}
\end{enumerate}

\section{Threats to Validity}

\subsection{Internal Validity}

\textbf{Threshold calibration:} Rule-based thresholds are frozen after 24-hour calibration and cryptographically hashed (SHA-256). The detector refuses to run on edited configurations, preventing post-hoc tuning on evaluation data.

\textbf{Fault switch caching:} Lambda functions cache the SSM fault parameter for 5 seconds. Detection delay measurements account for up to 2 seconds of this cache lag.

\textbf{Cold starts:} Lambda cold starts add 100-500ms latency that could trigger false positives. The calibration period captures typical cold-start patterns, and control periods measure false-positive rates.

\subsection{External Validity}

\textbf{Generalisability limits:} Results apply to AWS serverless order-processing microservices with synthetic workloads. Validity does not extend to:
\begin{itemize}
    \item Non-AWS platforms (Azure Functions, Google Cloud Run)
    \item Large-scale microservice systems ($>$10 services)
    \item Production traffic with complex user behaviour
    \item Microservice systems with deep call chains ($>$4 hops)
\end{itemize}

\textbf{Fault type coverage:} Four fault types cover common Lambda failure modes but not:
\begin{itemize}
    \item Data corruption or semantic errors
    \item External dependency outages (AWS service degradation)
    \item Configuration errors (IAM permissions, resource limits)
\end{itemize}

\subsection{Construct Validity}

\textbf{Detection timing:} We define TP as a detection within [injection\_start, injection\_end + 120s]. The 120s grace period accounts for metric aggregation lag in CloudWatch (60-second minimum period).

\textbf{Localisation ground truth:} For rig experiments, ground truth is the injected target (known by construction). For RCAEval, ground truth is the labeled root cause service in the benchmark dataset.

\subsection{Conclusion Validity}

\textbf{Multiple comparisons:} Holm-Bonferroni correction controls family-wise error rate within each hypothesis family.

\textbf{Non-parametric alternatives:} Normality tests precede parametric tests; if assumptions fail, we use Mann-Whitney U or permutation tests.

\textbf{Effect sizes:} Cohen's d (parametric) or rank-biserial (non-parametric) effect sizes are reported alongside p-values to assess practical significance.

\section{Ethical Considerations}

\textbf{No human participants:} This research involves no human subjects, surveys, or interviews.

\textbf{Synthetic data only:} All telemetry is generated from synthetic order payloads (deterministic fake customer IDs, SKUs). No personally identifiable information (PII) is collected or processed.

\textbf{Public benchmark data:} RCAEval is a published benchmark dataset under permissive license (Apache 2.0). We cite the original authors and comply with license terms.

\textbf{AWS Acceptable Use Policy:} Fault injection is confined to researcher-owned AWS account. No third-party systems are targeted. Budget limits prevent runaway costs.

\textbf{Research integrity:} False positives from control periods are reported. Negative results (if hypotheses are refuted) will be presented honestly. Xing et al.'s (2025) results are never misrepresented as defeated same-rig competitors.

\textbf{Classification:} NCI ethics review Scenario 2A (publicly available data + researcher's own infrastructure, no human subjects) - self-approved with supervisor notification.

\section{Summary}

This methodology establishes a rigorous experimental framework for positioning the rule-based approach on the accuracy-overhead Pareto frontier. The three-leg protocol avoids the apples-to-oranges problem of comparing trained vs untrained methods, while pre-committed expectations and frozen configurations prevent post-hoc optimisation. The next chapter details the design specifications of the AWS serverless artefact and the rule-based detection/localisation algorithms.

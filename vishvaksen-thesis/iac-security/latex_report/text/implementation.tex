\section{Implementation}
\label{sec:Implementation}
%% ==============================

The system is implemented in Python 3.12 with scikit-learn 1.4+ for machine learning, pandas for data management, and numpy for numerical operations. The implementation prioritizes reproducibility, testability, and deployment readiness. This section describes the key modules, deployment architecture, testing infrastructure, and implementation decisions.

\subsection{Core Modules}

\subsubsection{Dataset Generator (\texttt{src/data/iac\_dataset.py})}

The dataset generator implements the paired easy/hard, with/without-comment synthetic benchmark described in Section~\ref{sec:Methodology}. Key functions:

\begin{itemize}
  \item \texttt{generate\_dataset(n\_samples, seed, with\_comments)}: Main entry point. Returns a tuple \texttt{(snippets, labels)} where \texttt{snippets} is a list of IaC resource blocks and \texttt{labels} is a NumPy array of binary labels (0=safe, 1=misconfigured).
  
  \item \texttt{\_render\_filler(rng)}: Generates realistic-looking but semantically irrelevant configuration lines (instance type, region, owner, tags, retention period) with randomized values. These serve as noise to prevent the classifier from overfitting to snippet length or other spurious correlations.
  
  \item \texttt{EASY\_PATTERNS}: List of 4 dictionaries defining easy pattern templates. Each contains: resource type, unsafe value, safe value, unsafe comment, and safe comment.
  
  \item \texttt{HARD\_PATTERNS}: List of 2 dictionaries defining hard pattern templates. Each contains: resource type, field name, unsafe comment, and safe comment. The code line is constructed dynamically with a random 5-digit reference ID.
\end{itemize}

The generator uses \texttt{numpy.random.RandomState} for reproducible randomness. Given the same seed, the generator produces identical samples across runs, which is critical for reproducibility and for ensuring that rich/plain renderings are truly paired.

\subsubsection{Detector Implementations (\texttt{src/models/detectors.py})}

\paragraph{MLDetector Class:}
\begin{itemize}
  \item \textbf{Constructor:} Initializes TF-IDF vectorizer with custom token pattern \texttt{r"[A-Za-z0-9\_./:\textbackslash{}-]+"} to capture IaC-specific tokens (paths, IP addresses, version strings) and logistic regression with max 1000 iterations.
  
  \item \textbf{fit(snippets, labels):} Fits vectorizer on training snippets, transforms to TF-IDF features, fits logistic regression classifier. Returns self for method chaining.
  
  \item \textbf{predict(snippets):} Transforms snippets with fitted vectorizer, returns binary predictions (0 or 1).
  
  \item \textbf{predict\_proba(snippets):} Returns probability of class 1 (misconfigured) for each snippet. Used by hybrid detector for thresholding.
\end{itemize}

\paragraph{Rule-Based Detection:}
\begin{itemize}
  \item \texttt{RULE\_PATTERNS}: List of 4 compiled regex patterns, one per easy misconfiguration type. Patterns use flexible whitespace matching (\texttt{\textbackslash{}s*}) to handle varying code styles.
  
  \item \texttt{rule\_based\_flag(snippet)}: Returns True if any pattern matches the snippet, False otherwise. Implemented as \texttt{any(p.search(snippet) for p in RULE\_PATTERNS)}.
\end{itemize}

\paragraph{HybridDetector Class:}
\begin{itemize}
  \item \textbf{Constructor:} Takes a trained \texttt{MLDetector} and optional \texttt{ml\_threshold} (default 0.8). Stores references to both.
  
  \item \textbf{predict(snippets):} For each snippet:
  \begin{enumerate}
    \item Check if rule layer fires: if \texttt{rule\_based\_flag(snippet)} is True, return 1 immediately
    \item Otherwise, compute ML probability: \texttt{p = ml\_detector.predict\_proba([snippet])[0]}
    \item Return 1 if \texttt{p > ml\_threshold}, else 0
  \end{enumerate}
  Implemented as a list comprehension for efficiency.
\end{itemize}

\subsubsection{Training and Evaluation Script (\texttt{scripts/train\_and\_evaluate.py})}

The training script implements the full experimental protocol:

\begin{enumerate}
  \item \textbf{Seed Loop:} For each seed in \{42, 43, 44, 45, 46\}:
  \begin{itemize}
    \item Generate 1200-sample paired datasets (rich and plain)
    \item Verify labels match across renderings
    \item Perform stratified 70/30 train/test split
  \end{itemize}
  
  \item \textbf{Detector Training and Evaluation:}
  \begin{itemize}
    \item Train ML detector on rich context, evaluate on rich test set (RQ1 upper bound)
    \item Train ML detector on code-only, evaluate on code-only test set (RQ1 baseline gap)
    \item Evaluate rule-based detector on code-only test set (reference)
    \item Create hybrid detector wrapping code-only ML detector, evaluate on code-only test set (RQ2)
  \end{itemize}
  
  \item \textbf{Results Recording:}
  \begin{itemize}
    \item Compute precision, recall, F1 for each detector-seed combination
    \item Append to per-seed results list
    \item Write \texttt{results/results\_per\_seed.csv} and \texttt{results/results\_summary.csv}
    \item Export final trained ML detector to \texttt{src/lambda\_handler/model/ml\_detector.joblib} for deployment
  \end{itemize}
\end{enumerate}

The script uses \texttt{sklearn.metrics.precision\_score}, \texttt{recall\_score}, and \texttt{f1\_score} with \texttt{zero\_division=0} to handle edge cases gracefully.

\subsection{Deployment Architecture}

The system is designed for real-time IaC misconfiguration detection in a production environment. The deployment architecture uses AWS serverless components:

\subsubsection{Lambda Handler (\texttt{src/lambda\_handler/app.py})}

AWS Lambda function that applies the hybrid detector to IaC snippets submitted on a Kinesis stream. Key features:

\begin{itemize}
  \item \textbf{Model Loading:} On Lambda cold start, loads trained ML detector from \texttt{model/ml\_detector.joblib} using joblib. The hybrid detector is constructed on-the-fly wrapping this loaded model.
  
  \item \textbf{Event Processing:} For each Kinesis record:
  \begin{enumerate}
    \item Base64-decode the payload
    \item Extract IaC snippet string
    \item Apply hybrid detector: check rule layer, then ML confidence
    \item Construct response with: is\_misconfigured (bool), rule\_fired (bool), ml\_confidence (float)
  \end{enumerate}
  
  \item \textbf{Batch Processing:} Processes up to 100 records per invocation (Kinesis batch limit), returning a list of detection results.
\end{itemize}

\subsubsection{Infrastructure as Code (\texttt{template.yaml})}

AWS SAM template defining the deployment stack:

\begin{itemize}
  \item \textbf{Kinesis Stream:} \texttt{IaCSnippetStream} with 1 shard for development, configurable retention period
  \item \textbf{Lambda Function:} \texttt{HybridDetectorFunction} with:
  \begin{itemize}
    \item Python 3.12 runtime
    \item 512 MB memory (sufficient for scikit-learn model loading)
    \item 30-second timeout
    \item Kinesis event source mapping with batch size 100, starting position TRIM\_HORIZON
  \end{itemize}
  \item \textbf{IAM Permissions:} Lambda execution role with Kinesis read permissions, CloudWatch Logs write permissions
\end{itemize}

\subsubsection{CI/CD Pipeline (\texttt{.github/workflows/deploy.yml})}

GitHub Actions workflow automating the build, test, and deployment pipeline:

\begin{enumerate}
  \item \textbf{Trigger:} On push to \texttt{main} branch
  \item \textbf{Build:}
  \begin{itemize}
    \item Install Python dependencies
    \item Run training script to generate model artifacts
    \item Run pytest test suite (all 34 tests must pass)
  \end{itemize}
  \item \textbf{Deploy:}
  \begin{itemize}
    \item Configure AWS credentials from repository secrets
    \item Build SAM application
    \item Deploy to configured AWS region (us-east-1 by default)
    \item Tail Lambda logs for verification
  \end{itemize}
\end{enumerate}

\subsection{Testing Infrastructure}

A comprehensive pytest test suite validates all system components:

\subsubsection{Detector Tests (\texttt{tests/test\_detectors.py})}

13 tests covering:
\begin{itemize}
  \item \textbf{Rule-based detector:} Pattern matching for each misconfiguration type, false negative on safe configs, structural inability to detect hard patterns
  \item \textbf{ML detector:} Training convergence, prediction correctness, probability estimation
  \item \textbf{Hybrid detector:} Rule layer precedence, confidence thresholding, default threshold value (0.8)
  \item \textbf{Integration:} End-to-end pipeline from dataset generation through hybrid prediction
\end{itemize}

\subsubsection{Dataset Tests (\texttt{tests/test\_dataset.py})}

21 tests covering:
\begin{itemize}
  \item \textbf{Filler rendering:} Correct length, no unrendered placeholders, randomness
  \item \textbf{Pattern definitions:} Structure validation, distinguishability of easy patterns
  \item \textbf{Dataset generation:} Sample count, label distribution, comment presence/absence, reproducibility, paired consistency
  \item \textbf{Snippet structure:} Valid IaC resource blocks, presence of filler lines, correct reference ID format for hard patterns
\end{itemize}

All tests are executed via \texttt{make test} or directly with \texttt{pytest tests/ -v}.

\subsection{Build Automation (\texttt{Makefile})}

A Makefile provides standardized development workflows:

\begin{itemize}
  \item \texttt{make install}: Install all Python dependencies from \texttt{requirements.txt}
  \item \texttt{make test}: Run pytest suite with verbose output
  \item \texttt{make train}: Execute training and evaluation script
  \item \texttt{make clean}: Remove generated files, Python caches, test artifacts
  \item \texttt{make lint}: Run flake8 code quality checks (if installed)
  \item \texttt{make format}: Format code with black (if installed)
  \item \texttt{make all}: Full workflow: install, test, train
\end{itemize}

\subsection{Implementation Decisions and Rationale}

\subsubsection{TF-IDF vs. Transformer Models}

While War et al.~\cite{War25} use fine-tuned CodeBERT and LongFormer, this implementation uses TF-IDF + logistic regression for several reasons:

\begin{itemize}
  \item \textbf{Reproducibility:} No GPU required, no model downloads, runs on standard hardware
  \item \textbf{Transparency:} Simpler model makes it easier to understand what drives predictions
  \item \textbf{Baseline Alignment:} TF-IDF is the same feature family as the paper's own prior-work baseline
  \item \textbf{Qualitative Equivalence:} The goal is to reproduce the \emph{phenomenon} (precision collapse without comments), not the exact numbers
\end{itemize}

Empirical results confirm that TF-IDF exhibits the same qualitative behavior: perfect performance with comments, degraded precision without comments.

\subsubsection{Synthetic Benchmark Design}

Real-world IaC datasets (Ansible Galaxy, Puppet Forge) contain many confounds: varying comment quality, mixed security smell types, imbalanced class distributions. A synthetic benchmark offers several advantages:

\begin{itemize}
  \item \textbf{Controlled Ablation:} Paired with/without-comment renderings from identical underlying samples isolate the effect of comment removal
  \item \textbf{Explicit Hard/Easy Partition:} Makes the structural limitation of rules transparent rather than implicit
  \item \textbf{Label Quality:} Ground truth is determined by construction, not subjective human annotation
  \item \textbf{Balanced Distribution:} 50/50 safe/misconfigured, 50/50 easy/hard ensures metrics are not dominated by majority class
\end{itemize}

The trade-off is external validity: real IaC may have different hard/easy ratios or entirely different hard pattern categories. This is addressed in the Discussion (Section~\ref{sec:discussion}).

\subsubsection{Threshold Selection for Hybrid Detector}

The default threshold of 0.8 was chosen based on empirical observation: it is the lowest threshold at which precision reaches 1.000 in the code-only setting. Lower thresholds trade precision for recall; higher thresholds offer no further precision gain (already at ceiling). The threshold sweep (RQ3) characterizes the full trade-off curve, but 0.8 represents a reasonable default for a production system that prioritizes precision.

\section{Design Specification}
\label{sec:Design}
%% ==============================

\subsection{Easy and Hard Misconfiguration Patterns}
Each synthetic IaC snippet uses one of two pattern families:
\begin{itemize}
  \item \textbf{Easy} (4 patterns): safe and misconfigured versions use visibly different, enumerable literal values -- file mode \texttt{0777} vs. \texttt{0640}, protocol \texttt{http} vs. \texttt{https}, hash algorithm \texttt{sha1} vs. \texttt{sha256}, ingress CIDR \texttt{0.0.0.0/0} vs. a restricted range. Code tokens alone are genuinely sufficient to classify these.
  \item \textbf{Hard} (2 patterns): an opaque reference token (\texttt{password\_ref = "ref\_12345"}) whose numeric suffix carries no signal and is identical in shape whether safe or misconfigured. Only an accompanying comment (e.g. ``resolves to a hardcoded fallback password'' vs. ``resolves via the managed secrets vault'') reveals the true label. No regex or code-only classifier can distinguish these by construction.
\end{itemize}
Each generated sample is rendered in two paired forms from the same underlying random choices: \emph{with-comments} (rich context) and \emph{code-only} (comments stripped) -- mirroring War et al.'s own ablation axis.

\subsection{ML Detector (baseline reproduction)}
A TF-IDF vectorizer over snippet tokens feeding a logistic regression classifier -- the same statistical-feature-based family as the paper's own prior-work baseline (TF-IDF/BoW + Random Forest), used here in place of fine-tuned CodeBERT/LongFormer given no GPU/model-download budget for this project (see README scope note). Trained and evaluated separately on rich-context and code-only variants.

\subsection{Rule-Based Detector (reference)}
Four regular expressions matching the literal misconfigured value for each \emph{easy} pattern, independent of any comment. Structurally cannot recognise the \emph{hard} pattern at all -- there is no fixed literal to match.

\subsection{Hybrid Detector (proposed improvement)}
Flags a snippet as misconfigured if the rule layer fires, \emph{or} if the ML classifier's predicted probability exceeds a stricter threshold (0.8, vs. a plain 0.5 cutoff). This is deliberately not a simple OR of "rule fires OR ML predicts positive at 0.5" -- that would only ever add false positives on top of an already-low-precision code-only classifier. Gating the ML fallback at a stricter confidence threshold is what lets precision recover: unreliable, low-confidence guesses get filtered out rather than trusted.

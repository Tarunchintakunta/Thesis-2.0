# Ethics notes (input for the NCI Declaration of Ethics Consideration form)

Project: *Source-Free Log Anomaly Detection for AWS Serverless Applications* -
Kasireddy Vadicharla (25104047), MSc Cloud Computing, NCI.

These are factual notes about what the artefact does with data and systems,
to help fill in the official form. The form itself is filled in and signed by
the student.

## Scenario 1 - human participants

Not applicable. No surveys, interviews, user studies or personal data. All
traffic is synthetic and generated by the workload model in
`src/logad/collect/workload.py`.

## Scenario 2A - public secondary dataset (Loghub BGL)

* Dataset: Loghub BGL 2k sample, used only as the labelled *source* corpus of
  the transfer detector (D2).
* Permission: Loghub states its log datasets "are freely available for research
  or academic work" (https://github.com/logpai/loghub, README).
* Citation: Zhu et al. (2023), ISSRE, doi:10.1109/ISSRE59848.2023.00071.
* Handling: downloaded by `scripts/fetch_loghub.sh`, checksum verified, not
  redistributed in the repository.

## Scenario 3 - target systems

* The only system faults are injected into is the researcher's own Orders API:
  in the default mode a local Lambda runtime emulator on the researcher's
  machine; in live mode a LocalStack container on the researcher's machine or
  the researcher's own AWS account. No third-party system is touched.
* Live mode request rates stay low (fractions of a request per second on
  average) to stay within free-tier-safe limits and the AWS acceptable use
  policy.

## Privacy and data handling

* Request ids, account ids, IP addresses and order ids are stripped
  (`src/logad/collect/scrub.py`) before any analysis; the pipeline refuses to
  continue if an identifier survives scrubbing.
* Raw logs stay in `data/raw/` on the researcher's machine (gitignored).

## Research integrity

* The source-free detector's training window is fixed and certified clean
  before evaluation (`results/certification/`).
* Train / evaluation split is chronological only.
* The parser config is fingerprinted and never tuned between arms.
* One documented design amendment was made after the pilot (smoke) run and
  before the main collection: see `configs/detectors.yaml` (D1 primary model).
* Negative results are reported as they come out.

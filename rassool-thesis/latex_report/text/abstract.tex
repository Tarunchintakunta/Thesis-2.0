\begin{abstract}
Cloud-native NoSQL databases such as Amazon DynamoDB have emerged as a foundational component of serverless architectures, yet the performance–cost trade-offs introduced by partition-key design and capacity mode remain empirically underexplored. This study presents a factorial experimental \emph{design} that simultaneously varies partition-key design (simple, composite, and write-sharded keys: K1--K3) and capacity mode (on-demand and provisioned with auto-scaling) across four serverless workload profiles intended to be driven by AWS Lambda. Building on the latency and throughput measures established by \citet{pantelic2026benchmarking} for self-hosted NoSQL persistence under microservice workloads, this research extends the evaluation \emph{plan} to metered infrastructure by targeting throttling rates, consumed read and write capacity units (RCU/WCU), and absolute cost per 10,000 operations---dependent variables absent from self-hosted baselines. The artefact comprises Infrastructure-as-Code (Terraform), Lambda-based workload generators with Zipfian access distributions, CloudWatch-oriented metrics collectors, and statistical analysis scripts implementing two-way ANOVA with interaction effects. \textbf{Evaluation evidence in this report is moto-based simulation and pipeline validation only}; live AWS DynamoDB campaign cells are not yet filled, and no Cost Explorer pilot cross-check is claimed. An optional off-factorial K4 adaptive sharding code path exists in the repository but is outside the CA2 K1--K3 factorial and is not asserted as an empirical dominance result. Findings that answer the production performance--cost surface therefore remain contingent on a future live campaign under the alignment-first gate.
\end{abstract}

\section{Evaluation}

\textit{Note:} This study reports results from controlled simulation using moto (an in-memory DynamoDB-compatible emulator) to validate the experimental artefact and analysis pipeline. These results are \textbf{labelled as simulation data} and demonstrate the measurement methodology and statistical analysis framework. Execution on live AWS infrastructure requires the student's personal AWS account and budget allocation; the artefact is designed to facilitate third-party replication on production infrastructure. All simulation results are clearly marked as \texttt{data\_source = moto} and are not presented as empirical findings about production DynamoDB behaviour.

\subsection{Simulation Configuration}

The simulation was executed with the following parameters:

\begin{itemize}
    \item \textbf{Dataset:} 2,000 synthetic orders over 200 customers (scaled from 1M/10K for computational efficiency)
    \item \textbf{Workloads:} W3 (Mixed) and W4 (Burst) only (representative of sustained and variable load)
    \item \textbf{Replications:} 2 per configuration (n = 24 trials total)
    \item \textbf{Duration:} 20 seconds per trial (scaled from 300 seconds)
    \item \textbf{Rate:} 10 ops/s for sustained load, 50 ops/s for burst (scaled from 200/1000 ops/s)
    \item \textbf{Zipfian s:} 1.070916 (same as full-scale design)
\end{itemize}

\subsection{Limitations of Simulation}

Simulation using moto serves exclusively to validate the experimental artefact (infrastructure deployment, workload generation, metrics collection, statistical analysis) and does not constitute empirical evidence about production DynamoDB performance. Key limitations:

\begin{enumerate}
    \item \textbf{No network latency:} Moto executes in-process; production DynamoDB incurs inter-availability-zone network latency (1–5 ms).
    \item \textbf{No adaptive capacity:} Moto does not implement DynamoDB's adaptive capacity or burst capacity mechanisms \citep{aws2025adaptive}, which are critical to understanding hot-key throttling behaviour.
    \item \textbf{Simplified throttling:} Moto's provisioned-mode throttling is deterministic (exceeding reserved capacity immediately returns \texttt{ProvisionedThroughputExceededException}); production DynamoDB applies admission control probabilistically with burst allowances.
    \item \textbf{No auto-scaling delays:} Moto does not emulate the 10–60 second latency of Application Auto Scaling adjustments in production.
    \item \textbf{No multi-tenancy effects:} Moto is single-tenant; production DynamoDB may exhibit noisy-neighbour effects under high multi-tenant load.
\end{enumerate}

\subsection{Validation of Experimental Artefact}

The simulation successfully validates:

\begin{enumerate}
    \item \textbf{Infrastructure deployment:} Terraform provisions all six table configurations correctly, as confirmed by \texttt{terraform validate} and deployment to moto.
    \item \textbf{Workload generation:} Lambda handler generates correct operation sequences (verified by operation counts and read/write ratios matching workload specifications).
    \item \textbf{Zipfian distribution:} Kolmogorov-Smirnov test confirms that sampled keys match the target Zipfian distribution (p = [MOTO SIM: 0.42] $>$ 0.05).
    \item \textbf{K3 scatter-gather:} K3 read operations correctly query all 10 shards and return merged results (validated by unit tests).
    \item \textbf{Metrics collection:} Per-operation latency, throttle counts, and consumed capacity are correctly recorded and aggregated.
    \item \textbf{Cost modelling:} Cost calculations apply \texttt{eu-west-1} list prices from \texttt{config/prices.yaml} to consumed RCU/WCU in the analysis code. This is \textbf{not} a live AWS Cost Explorer cross-check; no Cost Explorer export is committed.
    \item \textbf{Statistical analysis:} ANOVA, post-hoc tests, and visualisations execute without errors on simulation fixtures and produce interpretable output.
\end{enumerate}

The artefact is designed for later live AWS deployment under the alignment-first gate; moto validation alone does \textbf{not} constitute production DynamoDB evidence.

\section{Conclusion}
\label{sec:conclusion}

\subsection{Summary of Contributions}

This research presented SecureFL-IDS, a privacy-preserving federated intrusion detection framework for cloud-native environments. The work makes four primary contributions:

\begin{enumerate}
    \item \textbf{Baseline Replication:} Implementation of the PP-FL-DP-IDS approach by \citet{saklani2026privacy} as a local federated simulation baseline.
    
    \item \textbf{Enhanced Framework:} SecureFL-IDS adds adaptive differential privacy, top-k compression hooks, and a CNN-LSTM hybrid architecture in code. These enhancements are \emph{implemented}; their benefit is \textbf{not} demonstrated as literature-level 93.7\% accuracy / $-45\%$ communication wins on the committed PoC.
    
    \item \textbf{Honest PoC Evaluation:} Committed results (\texttt{results/comparison/results.json}): baseline accuracy $0.793$ (F1 $\approx 0.019$) vs improved accuracy $0.800$ (F1 $0.0$); communication $1.83$ vs $3.12$~MB/round on synthetic data.
    
    \item \textbf{Open-Source Artefact:} Modular codebase, local simulation, tests, and a Terraform scaffold (\texttt{securefl-ids/terraform/}) that has \textbf{not} been applied. No Docker/Kubernetes/live-AWS execution is claimed.
\end{enumerate}

\subsection{Research Question Answered (within PoC scope)}

The primary research question asked:

\begin{quote}
\textit{What is the effect of combining Federated Learning with Differential Privacy and communication-efficient aggregation on the accuracy, privacy preservation, and resource efficiency of cloud-native intrusion detection systems?}
\end{quote}

Within the committed PoC:

\begin{itemize}
    \item \textbf{Accuracy:} Marginal change ($0.793 \rightarrow 0.800$) on synthetic data; not a validated $+2.5\%$ production claim.
    \item \textbf{F1:} Near zero for both arms---models fail to separate the minority (attack) class under the synthetic setup.
    \item \textbf{Communication:} Improved arm used \emph{more} MB/round; the $-45\%$ efficiency claim is unsupported by \texttt{results.json}.
    \item \textbf{Deployment:} Local simulation only; cloud-native orchestration not evaluated.
\end{itemize}

###{Implications for Practice}

Practitioners should treat this artefact as a research prototype: FL+DP plumbing exists, but detection quality and communication efficiency must be re-measured on full UNSW-NB15 (or equivalent) before any production integration narrative (including AWS GuardDuty-style services or Kubernetes orchestration).

\subsection{Limitations and Constraints}

\begin{enumerate}
    \item Local simulation only; Terraform present but not applied; no Docker/K8s evidence.
    \item Synthetic data drives near-zero F1.
    \item No centralised IDS comparator.
    \item Honest-but-curious threat model only.
    \item No live metered cloud campaign.
\end{enumerate}

\subsection{Future Work}

Full UNSW-NB15 training, centralised baseline, multi-class detection, Byzantine-robust aggregation, and---only after the alignment-first gate---optional live AWS evaluation using the existing Terraform scaffold.

\subsection{Closing Remarks}

SecureFL-IDS contributes a reproducible FL+DP IDS codebase and an honest PoC. Claimed metrics match committed results; inflated accuracy/F1/communication and Docker/K8s/AWS production claims are deliberately excluded. CA2 alignment remains incomplete pending fuller experiments and (if required) live cloud evaluation.

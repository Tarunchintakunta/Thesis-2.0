\section{Evaluation}
\label{sec:evaluation}

This section reports \textbf{committed proof-of-concept results only}. All numeric claims below match \texttt{results/comparison/results.json} unless explicitly labelled as baseline-paper reference or future work. No Docker, Kubernetes, or live AWS campaign was executed.

\subsection{Experimental Results}

\subsubsection{Detection Performance}

Table~\ref{tab:detection_results} presents the actual experimental results from 30-round training on synthetic UNSW-NB15-derived data (5 federated clients, local multi-process simulation).

\begin{table}[h]
\centering
\begin{tabular}{lcc}
\toprule
\textbf{Metric} & \textbf{Baseline} & \textbf{SecureFL-IDS} \\
\midrule
Accuracy & 0.7930 & 0.8000 \\
F1-Score & 0.0190 & 0.0000 \\
Avg Comm (MB/round) & 1.83 & 3.12 \\
\bottomrule
\end{tabular}
\caption{Committed PoC results (synthetic data, 30 rounds, 5 clients; source: \texttt{results/comparison/results.json})}
\label{tab:detection_results}
\end{table}

\textbf{Honest interpretation:}

\begin{itemize}
    \item Accuracy is $\approx 0.793$--$0.800$; the improved variant does \emph{not} demonstrate a large accuracy win on this PoC.
    \item F1-scores are near zero (baseline $\approx 0.019$, improved $0.0$), consistent with majority-class prediction on a simplified synthetic feature space.
    \item These figures must not be restated as 91--94\% accuracy or $\sim$90\% F1; those values belong to the Saklani et al.\ baseline paper on full UNSW-NB15, not to this artefact's committed run.
\end{itemize}

\textbf{Baseline-paper reference (not this PoC):} \citet{saklani2026privacy} report $\approx 91.8\%$ accuracy on full UNSW-NB15. Reaching comparable numbers would require the full feature set, larger samples, longer training, and class balancing---none of which are evidenced by the committed \texttt{results.json}.

\textbf{Observation:} The improved CNN-LSTM model transmits \emph{more} bytes per round than the baseline CNN in this PoC. A $-45\%$ communication reduction is \textbf{not} achieved in the committed results; compression exists in code but is offset by larger model size. Any $-40$--$50\%$ target is aspirational pending tuning on full data.

\subsubsection{Convergence}

Both arms ran for a fixed $30$ rounds in the PoC. Claims of ``$93\%$ by round 35'' or ``$30\%$ faster convergence'' are \textbf{not} supported by \texttt{results.json} and are omitted.

\subsection{What was not evaluated}

\begin{itemize}
    \item Privacy--utility sweep tables with fabricated $\epsilon$ rows (not in committed results)
    \item Ablation / scalability tables citing $0.937$ accuracy (not in committed results)
    \item Statistical significance tests on the PoC (not committed)
    \item Centralised IDS comparator
    \item Live AWS, Docker Compose, or Kubernetes deployments (Terraform scaffold present under \texttt{securefl-ids/terraform/} but \textbf{not applied})
\end{itemize}

\subsection{Comparison with related work (positioning only)}

Related federated IDS papers (including Saklani et al.) report higher accuracy on full benchmarks. This PoC does \textbf{not} claim to outperform them numerically. SecureFL-IDS is positioned as an FL+DP artefact with adaptive privacy and compression \emph{hooks}, evaluated honestly on synthetic local simulation.

\subsection{Limitations}

\begin{itemize}
    \item Local simulation only; no distributed cloud evaluation
    \item Synthetic dataset (20 features / limited samples) when full UNSW-NB15 unavailable
    \item Binary classification; near-zero F1 under class imbalance
    \item Honest-but-curious threat model only
    \item Terraform exists but was not applied; no production AWS claim
\end{itemize}

\subsection{Threats to validity}

\begin{itemize}
    \item Single PoC configuration; not multi-seed averaged
    \item Simulated non-IID may not match real tenant heterogeneity
    \item Local timing does not capture network latency or orchestration overhead
\end{itemize}

The controlled PoC validates that the implementation runs and emits metrics; it does \textbf{not} establish production-grade detection performance or cloud-native deployment readiness.

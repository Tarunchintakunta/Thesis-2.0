\section{Evaluation}
\label{sec:Evaluation}
%% ==================

Table~\ref{tab:results} reports mean $\pm$ standard deviation across 5 seeds (42-46) on held-out test data, bound to the committed artefact \texttt{mhsa-tdl-framework/results/results\_summary.csv} (per-seed rows in \texttt{results\_per\_seed.csv}). Model weight initialisation and data-loader shuffling are seeded per run (not just the synthetic data generator), so these numbers are reproducible by re-running \texttt{scripts/train\_and\_evaluate.py}.

%% ===============================
\subsection{Experiment 1: Reactive vs. Proactive}
\label{sec:evalOne}
%% ===============================

Both attention models overwhelmingly outperform the reactive threshold baseline at anticipating violations before they occur (Transient Recall 0.86-0.88 vs. 0.025). This is structural, not a modelling artefact: the threshold baseline only ever sees the history window, so unless a violation has already started before the window ends, it cannot know one is coming. This confirms Thapliyal's central claim -- proactive, attention-based prediction meaningfully beats reactive threshold monitoring -- transfers from the SLA/colocation setting to cluster telemetry.

%% ===============================
\subsection{Experiment 2: Reproducing the Baseline Paper's Gap}
\label{sec:evalTwo}
%% ===============================

The reproduced baseline (MHSA-PerHead) shows a Transient Underprediction Bias of 0.29 severity levels -- i.e. when a real L1/L2 violation occurs inside a transient window, the model's prediction is on average 0.29 levels too low. This reproduces, on cluster telemetry, the same failure mode Thapliyal reports for the power-draw head on colocation telemetry: strictly independent per-metric heads underpredict severity during volatile, correlated bursts.

%% ===============================
\subsection{Experiment 3: Cross-Head Fusion}
\label{sec:evalThree}
%% ===============================

Adding the cross-head fusion layer (MHSA-Fused) moves both of the paper's targeted metrics in the right direction: Transient Recall rises from 0.864 to 0.884, and Underprediction Bias falls from 0.290 to 0.273 ($\sim$6\% relative reduction). This comes at a small cost to the metrics the paper does not specifically flag as a gap -- overall Accuracy drops from 0.873 to 0.863 and Macro-F1 from 0.565 to 0.560. None of these four differences exceed one standard deviation across the 5 seeds, so the honest reading is: a real, directionally consistent, but statistically modest improvement on the targeted gap, not a decisive win.

%% ===============================
\subsection{Discussion}
\label{sec:discussion}
%% ===============================

An earlier run of this same experiment (before model-weight initialisation and data-loader shuffling were seeded) showed a much larger apparent improvement ($\sim$20\% bias reduction). That result did not replicate once training randomness was properly controlled -- it was luck in the random seed, not a real effect, which is itself a useful (if uncomfortable) finding: unseeded neural network comparisons in a report this size can easily produce a result that looks like a clean win but isn't. The properly-seeded, 5-seed result reported above is the one that should be trusted.

The remaining effect is real but modest, and is consistent with the underlying mechanism being subtle: the shared backbone already partially mixes cross-metric information before the heads split, so the fusion layer is refining an existing signal rather than introducing information that was completely unavailable before. A cleaner, larger effect would likely need either a longer training budget, an explicit auxiliary loss that penalises underprediction directly (rather than a generic cross-entropy loss), or a larger, more diverse burst-pattern vocabulary in the synthetic generator. These are noted as future work in Section~\ref{sec:Conclusion} rather than pursued further here, given the intentionally small scope of this benchmark.

The threshold baseline's near-zero transient recall should not be read as ``threshold monitoring is bad'' in general -- it is doing exactly what reactive monitoring is designed to do (report current state), and is being evaluated here specifically on a forecasting task it was never meant to solve.

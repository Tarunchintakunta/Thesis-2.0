\section{Related Work}
\label{sec:rw}

Cluster and data-center monitoring has traditionally relied on static threshold rules applied to individual telemetry metrics (CPU, memory, disk, network). Such reactive monitoring only flags a problem once a metric has already crossed its limit, leaving no lead time for remediation.

\subsection{Baseline: Multi-Head Attention for Telemetry-Based Violation Prediction}
The baseline for this project is Thapliyal \cite{Thapliyal26}, ``A Multi-Head Attention Approach for SLA Compliance Monitoring in Data Centers'' (arXiv:2605.05354, accepted at the 46th IEEE ICDCS, May 2026). The paper trains a per-customer transformer in which each attention head is dedicated 1-to-1 to a single telemetry rule (power draw, temperature, humidity), predicting a None/Level-1/Level-2 violation label 30 minutes ahead from historical sensor windows. This directly targets the same problem this project addresses -- proactive, rather than reactive, violation prediction -- but for colocation SLA metrics rather than cluster health metrics.

Critically, the paper's own reported results expose a specific weakness of the strict one-head-per-metric design: the power-draw head shows ``a skewed, bimodal error profile ... with systematic underprediction during high-load transients, a direct consequence of instantaneous load volatility.'' The authors attribute this to the architecture's decoupled heads never exchanging information with each other, even though their own data shows power and temperature are correlated.

\subsection{The Gap This Project Targets}
Because each head in Thapliyal's design is trained and read out independently, a head has no way to use another metric's precursor signal to anticipate its own metric's future violation. This project reproduces the strict per-head architecture as a baseline (Section~\ref{sec:Design}), confirms the same underprediction pattern on synthetic cluster telemetry, and then evaluates a cross-head fusion layer that lets the per-metric head representations attend to one another before classification.

\subsection{Threshold-Based Monitoring as a Second Baseline}
Traditional reactive threshold monitoring (flagging a violation only once a metric has already crossed its band in the observed window) is retained as a second, non-attention baseline, consistent with how Thapliyal frames the case for proactive monitoring against the industry-standard reactive approach.

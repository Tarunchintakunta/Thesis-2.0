\section{Design Specification}
\label{sec:Design}
%% ==============================

This section specifies the three model architectures evaluated in this project: a shared temporal backbone (Section~\ref{subsec:backbone}), the strict per-head baseline reproduction (Section~\ref{subsec:perhead}), the proposed cross-head fusion improvement (Section~\ref{subsec:fused}), and the traditional threshold baseline (Section~\ref{subsec:threshold}). Figure~\ref{fig:architecture} illustrates the architectural differences between the baseline and fused models.

\subsection{Shared Temporal Backbone}
\label{subsec:backbone}

Both attention-based models (MHSA-PerHead and MHSA-Fused) share a common temporal encoder that processes the 10-step history window before any per-metric specialization occurs. This backbone consists of four stages:

\begin{enumerate}
  \item \textbf{Input Embedding}: The 4 raw metrics (CPU, memory, disk, network) at each timestep are projected into a 32-dimensional embedding space via a learned linear transformation $W_{\text{embed}} \in \mathbb{R}^{4 \times 32}$. This produces a sequence of 10 embedding vectors $\mathbf{e}_t \in \mathbb{R}^{32}$ for $t = 0, \ldots, 9$.

  \item \textbf{Positional Encoding}: A learned positional encoding $\mathbf{p}_t \in \mathbb{R}^{32}$ is added to each embedding to inject temporal order information:
  \begin{equation}
  \mathbf{x}_t = \mathbf{e}_t + \mathbf{p}_t
  \end{equation}
  The positional encodings are initialized randomly and learned during training, rather than using fixed sinusoidal encodings as in the original Transformer~\cite{Vaswani17}.

  \item \textbf{Multi-Head Self-Attention}: A standard multi-head self-attention block with 4 heads (head dimension $d_h = 8$, total model dimension $d_{\text{model}} = 32$) processes the sequence $\{\mathbf{x}_0, \ldots, \mathbf{x}_9\}$. For each head $h$, the attention is computed as:
  \begin{equation}
  \text{Attention}_h(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_h}}\right) \mathbf{V}
  \end{equation}
  where $\mathbf{Q} = \mathbf{X} W_h^Q$, $\mathbf{K} = \mathbf{X} W_h^K$, $\mathbf{V} = \mathbf{X} W_h^V$, and $W_h^Q, W_h^K, W_h^V \in \mathbb{R}^{32 \times 8}$ are learned projection matrices. The outputs of all 4 heads are concatenated and projected back to dimension 32:
  \begin{equation}
  \text{MultiHead}(\mathbf{X}) = \text{Concat}(\text{Attention}_1, \ldots, \text{Attention}_4) W^O
  \end{equation}
  where $W^O \in \mathbb{R}^{32 \times 32}$. A residual connection and layer normalization follow:
  \begin{equation}
  \mathbf{X}' = \text{LayerNorm}(\mathbf{X} + \text{MultiHead}(\mathbf{X}))
  \end{equation}

  \item \textbf{Feed-Forward Network}: A two-layer feed-forward network with ReLU activation is applied position-wise:
  \begin{equation}
  \text{FFN}(\mathbf{x}) = W_2 \cdot \text{ReLU}(W_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2
  \end{equation}
  where $W_1 \in \mathbb{R}^{32 \times 128}$, $W_2 \in \mathbb{R}^{128 \times 32}$. Another residual connection and layer normalization follow:
  \begin{equation}
  \mathbf{X}'' = \text{LayerNorm}(\mathbf{X}' + \text{FFN}(\mathbf{X}'))
  \end{equation}
\end{enumerate}

The output of the backbone is a sequence of 10 contextualized embedding vectors $\{\mathbf{z}_0, \ldots, \mathbf{z}_9\}$, where $\mathbf{z}_t \in \mathbb{R}^{32}$ encodes the joint temporal and cross-metric information at timestep $t$. This corresponds to the ``Transformer encoder backbone'' stage of Thapliyal's architecture~\cite{Thapliyal26}, which jointly encodes all metrics before any per-metric specialization.

\subsection{MHSA-PerHead (Baseline Reproduction)}
\label{subsec:perhead}

The baseline model (MHSA-PerHead) implements the strict one-head-per-metric architecture described in the baseline paper~\cite{Thapliyal26}. After the shared backbone, the model splits into 4 independent per-metric heads, each responsible for one metric (CPU, memory, disk, or network).

\textbf{Manual Head Split}: The 32-dimensional output of the backbone at the last timestep ($\mathbf{z}_9$) is split into 4 non-overlapping 8-dimensional head vectors:
\begin{equation}
\mathbf{h}_m = \mathbf{z}_9[8m : 8(m+1)] \quad \text{for } m \in \{0, 1, 2, 3\}
\end{equation}
where $\mathbf{h}_m \in \mathbb{R}^8$ is the head vector for metric $m$.

\textbf{Per-Head Attention}: Each head $m$ computes its own attention over the full 10-step window. The query is derived from the head vector $\mathbf{h}_m$, and the keys and values are derived from the full sequence $\{\mathbf{z}_0, \ldots, \mathbf{z}_9\}$ (also split per head):
\begin{equation}
\mathbf{q}_m = W_m^Q \mathbf{h}_m, \quad \mathbf{K}_m = W_m^K \mathbf{Z}_m, \quad \mathbf{V}_m = W_m^V \mathbf{Z}_m
\end{equation}
where $\mathbf{Z}_m \in \mathbb{R}^{10 \times 8}$ is the sequence of head vectors for metric $m$ over all 10 timesteps. The attention weights and context vector are:
\begin{equation}
\alpha_m = \text{softmax}\left(\frac{\mathbf{q}_m \mathbf{K}_m^T}{\sqrt{8}}\right), \quad \mathbf{c}_m = \alpha_m \mathbf{V}_m
\end{equation}
where $\mathbf{c}_m \in \mathbb{R}^8$ is the per-head context vector.

\textbf{Independent Classifiers}: Each head's context vector $\mathbf{c}_m$ is passed to an independent 2-layer feed-forward classifier:
\begin{equation}
\mathbf{o}_m = W_m^{(2)} \cdot \text{ReLU}(W_m^{(1)} \mathbf{c}_m + \mathbf{b}_m^{(1)}) + \mathbf{b}_m^{(2)}
\end{equation}
where $W_m^{(1)} \in \mathbb{R}^{8 \times 16}$, $W_m^{(2)} \in \mathbb{R}^{16 \times 3}$, and $\mathbf{o}_m \in \mathbb{R}^3$ is the logits vector over the three classes (None, L1, L2). The predicted class is $\hat{y}_m = \arg\max \mathbf{o}_m$.

\textbf{Key Property}: No information is shared across heads after the split. Each head independently predicts its metric's violation label based only on its own 8-dimensional subspace of the backbone's output. This is the strict 1-to-1 head-to-metric mapping that the baseline paper identifies as the source of systematic underprediction during transients with cross-metric dependencies.

\subsection{MHSA-Fused (Proposed Improvement)}
\label{subsec:fused}

The fused model (MHSA-Fused) is identical to MHSA-PerHead up to the point where per-head context vectors are computed. The key difference is the addition of a single-layer self-attention block (\texttt{CrossHeadFusion}) that lets the 4 head context vectors attend to each other before classification.

\textbf{Cross-Head Fusion}: After computing the per-head context vectors $\{\mathbf{c}_0, \mathbf{c}_1, \mathbf{c}_2, \mathbf{c}_3\}$ (each $\in \mathbb{R}^8$), they are stacked into a 4-token sequence $\mathbf{C} \in \mathbb{R}^{4 \times 8}$. A single-layer self-attention block processes this sequence:
\begin{equation}
\mathbf{Q}_{\text{fuse}} = \mathbf{C} W_{\text{fuse}}^Q, \quad \mathbf{K}_{\text{fuse}} = \mathbf{C} W_{\text{fuse}}^K, \quad \mathbf{V}_{\text{fuse}} = \mathbf{C} W_{\text{fuse}}^V
\end{equation}
\begin{equation}
\mathbf{C}_{\text{fused}} = \text{softmax}\left(\frac{\mathbf{Q}_{\text{fuse}} \mathbf{K}_{\text{fuse}}^T}{\sqrt{8}}\right) \mathbf{V}_{\text{fuse}}
\end{equation}
where $W_{\text{fuse}}^Q, W_{\text{fuse}}^K, W_{\text{fuse}}^V \in \mathbb{R}^{8 \times 8}$. A residual connection and layer normalization follow:
\begin{equation}
\mathbf{C}' = \text{LayerNorm}(\mathbf{C} + \mathbf{C}_{\text{fused}})
\end{equation}

\textbf{Fused Classifiers}: Each row of $\mathbf{C}'$ (now $\mathbf{c}'_m \in \mathbb{R}^8$ for metric $m$) is passed to the same per-metric classifier architecture as in MHSA-PerHead:
\begin{equation}
\mathbf{o}_m = W_m^{(2)} \cdot \text{ReLU}(W_m^{(1)} \mathbf{c}'_m + \mathbf{b}_m^{(1)}) + \mathbf{b}_m^{(2)}
\end{equation}

\textbf{Key Property}: The fusion layer is the minimal architectural change needed to let e.g. the CPU head's classifier be informed by what the network head is currently observing. The attention weights $\alpha_{ij} = \text{softmax}(\mathbf{q}_i \mathbf{k}_j^T / \sqrt{8})$ quantify how much head $i$ attends to head $j$. If the network head's context vector contains an early signal of a CPU spike (because the shared backbone has already encoded some cross-metric correlation), the fusion layer allows the CPU head to leverage that signal before making its final prediction.

\subsection{Threshold Baseline}
\label{subsec:threshold}

A traditional reactive threshold monitor is included as a second baseline, representing the industry-standard practice that the baseline paper~\cite{Thapliyal26} positions itself against. For each metric, the threshold baseline:
\begin{enumerate}
  \item Computes the peak value over the last 3 steps of the \emph{history} window only (timesteps 7, 8, 9): $v_{\text{peak}}^{(m)} = \max_{t \in \{7, 8, 9\}} x_t^{(m)}$.
  \item Applies the same None/L1/L2 thresholds used to generate ground-truth labels:
  \begin{equation}
  \hat{y}_{\text{threshold}}^{(m)} = \begin{cases}
  \text{None} & \text{if } v_{\text{peak}}^{(m)} < 0.6 \\
  \text{L1} & \text{if } 0.6 \leq v_{\text{peak}}^{(m)} < 0.8 \\
  \text{L2} & \text{if } v_{\text{peak}}^{(m)} \geq 0.8
  \end{cases}
  \end{equation}
\end{enumerate}

The threshold baseline cannot see the future window (timesteps 10--14) and therefore can only detect violations that have already started in the observable history. This is by design: reactive monitoring is structurally limited to reporting current state, not predicting future state. The baseline's low transient recall (Section~\ref{sec:Evaluation}) reflects this limitation, not a modelling failure.

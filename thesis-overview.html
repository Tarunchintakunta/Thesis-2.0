SQS Reliability & Recovery

Anjaneya Reddy Gurram · 24288853 anji-thesis/sqs-reliability-recovery

How does Amazon SQS configuration affect message reliability and recovery under injected consumer and downstream failures?

Methodology

Two-arm experiment — sync API vs SQS+DLQ pipeline. Randomised config matrix: visibility timeout (30–600 s), retry limits, batch sizes. Four fault modes injected via SSM switch. 350 simulated runs.

Novel Contribution

DIVE — Dynamic Intelligent Visibility Extender

Adapts SQS visibility timeout per-message based on retry count instead of static backoff. Recovers pipelines in <30 s vs 300+ s baseline. Halves unnecessary Lambda invocations.

Baseline

Kyrychenko et al. (2025) — SQS batch config optimisation under steady-state healthy consumers.

Stack

  • AWS SAM · SQS + DLQ · Lambda · DynamoDB
  • Python 3.11+ · moto · local simulator
  • ReportBatchItemFailures

Source-Free Log Anomaly Detection

Kasireddy Vadicharla · 25104047 kasi-thesis/serverless-log-anomaly

How much F1 does a source-free one-class detector forfeit versus a transfer-based detector (ELFA-Log) on the same serverless CloudWatch logs under faults from a published serverless fault distribution?

Methodology

Lambda runtime emulator generates ~1.2M log lines/seed. 3 seeds × 720 injected faults across 4 categories. 60 s windowed features — count view (D1) and semantic view (D2). Wilcoxon paired tests, Friedman, Holm correction.

Novel Contribution

D4 — Context-Aware OC-SVM

Temporal masking suppresses anomaly signals during cold-start windows. Achieves F1 0.957, beating ELFA-Log transfer baseline (0.836) and threshold alarms (0.936). Solves "benign elasticity poisoning."

Baseline

Zhao et al. (2025) — ELFA-Log cross-system log anomaly detection via pseudo-labelling and feature alignment.

Stack

  • Lambda emulator · CloudWatch · Loghub BGL
  • Drain parser · OC-SVM · Isolation Forest
  • CORAL feature alignment
Artifact done F1 = 0.957 Baseline beaten Sensitivity run AWS runs Report

Lambda Cold-Start Isolation

Kondragunta Lakshmi Chaitanya · 25171216 chaitanya-thesis/lambda-coldstart-isolation

How much of AWS Lambda cold-start latency can be removed by developer-adjustable controls — runtime, package size, memory, and warming — and at what cost?

Methodology

6 Lambda packages across Python 3.12, Node.js 20, Java 21 — each with default and optimised variants. ANOVA/Kruskal-Wallis for H1 (runtime), Mann-Whitney U for H2 (package), Wilcoxon for H3 (warming), Holm-Bonferroni family control.

Novel Contribution

Python Pre-compiled Bytecode Optimisation (.pyc-only layer)

Eliminates AST parsing at cold start by deploying compiled .pyc files. Proxy benchmark: 70–75% init latency reduction (~980 ms → ~233 ms). Decision matrix weighing cost vs latency gain.

Baseline

Bluemke & Zdanowski (2025) — AWS Lambda configuration evaluation (Python only, no Init Duration isolation).

Stack

  • AWS SAM · 8 arm64 Lambda functions
  • Python · Node.js · Java 21 (Corretto)
  • EventBridge warmer · CloudWatch REPORT parsing

DynamoDB Partition-Key & Capacity

Rasool Basha Durbesula · 24205478 rassool-thesis/dynamodb-pk-capacity-eval

How do partition-key design and capacity mode interact to affect performance and cost in DynamoDB under realistic serverless workloads?

Methodology

3 × 2 × 4 factorial design (key design × capacity mode × workload). 1M synthetic orders, Zipf s = 1.07 (90% traffic on 10% keys). 30 batches per cell in randomised blocks. Two-way ANOVA with interaction, Tukey post-hoc, Holm correction.

Novel Contribution

K4 — Adaptive Tiered Sharding

Popularity-aware routing: hot keys (rank < 1000) use N=10 shards, cold keys use N=1. Eliminates K3's 10× read penalty on the long tail while retaining K3's write-throttle protection. ~90% RCU reduction for mixed/read-heavy workloads.

Baseline

Pantelić et al. (2026) — SQL/NoSQL benchmarking under variable workloads (self-hosted, no serverless cost metrics).

Stack

  • Terraform · DynamoDB (6 tables) · Lambda
  • moto · Zipf workload generator
  • BatchWriteItem seeder · target-tracking auto-scale

Lambda Idempotency Under Retries

Vikas Reddy Amanagantti · X25178849 vikas-thesis/lambda-idempotency-eval

How do application-level idempotency strategies (plain put, conditional put, idempotency key) affect duplicate state changes, latency, and capacity under injected retries on Lambda + DynamoDB?

Methodology

3 write paths × 3 retry multiplicities (1, 2, 5). Injected timeouts after commit so duplicates are deterministic. Mutation ground truth from DynamoDB Streams. z-test/chi-square for duplicates, Welch/Mann-Whitney for latency and capacity, Holm correction.

Key Paths

  • P1 Plain put — writes again on redelivery (duplicate)
  • P2 Conditional put — attribute_not_exists(pk)
  • P3 Idempotency key — Powertools pattern, stored result replay

Baseline

Qi et al. (2025) — Halfmoon asymmetric logging for retry correctness (custom runtime, not stock Lambda).

Stack

  • Terraform · Lambda · DynamoDB + Streams
  • moto · CloudWatch cross-check
  • 60 tests · budget ~$0.17

Serverless Fault Localisation

Yashaswini Penumarthi · 24262404 yashaswini-thesis/serverless-fault-localisation

How close do plain CloudWatch rules plus X-Ray dependency ranking get to learned root-cause methods in a serverless microservice app, and what do they cost in telemetry overhead?

Methodology

Three-leg evaluation: (1) ceiling from Xing et al. quoted, (2) like-for-like rule arm vs RCAEval baselines on 90 public benchmark cases, (3) telemetry overhead on live rig. 4 fault types, ground-truth schedule, open-loop load gen at 2–10 rps.

Architecture

  • REST API → orders-api → inventory, payments, notifications
  • SSM-based fault injection (4 types)
  • CloudWatch rules (3σ/frozen p99) + X-Ray ranker
  • RCAEval RE2-OB comparison (90 offline cases)

Baseline

Xing et al. (2025) — Learned RCA for microservice architectures (not a same-rig competitor; ceiling reference only).

Stack

  • AWS SAM · API Gateway · 4 Lambda fns
  • X-Ray · CloudWatch · DynamoDB · SSM
  • RCAEval public benchmark data

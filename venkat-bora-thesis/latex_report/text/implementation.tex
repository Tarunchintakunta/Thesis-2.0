\section{Key Implementation Details}

\subsection{NumPy Threading Control}

To isolate application-level parallelism from library-level parallelism:

\begin{verbatim}
import os
os.environ['OMP_NUM_THREADS'] = '1'
os.environ['OPENBLAS_NUM_THREADS'] = '1'
os.environ['MKL_NUM_THREADS'] = '1'
\end{verbatim}

Without this control, NumPy's internal threading would interfere with our threading model measurements, creating nested parallelism that obfuscates results.

\subsection{Multiprocessing Pickle Constraint}

Python's multiprocessing requires that worker functions be picklable. Nested functions fail:

\begin{verbatim}
# FAILS: Nested function can't be pickled
def matrix_multiply_multiprocess(A, B):
    def compute_block(start, end):  # Not picklable!
        return A[start:end, :] @ B
    with ProcessPoolExecutor() as executor:
        executor.submit(compute_block, ...)  # Error!
\end{verbatim}

Solution: Define worker functions at module level:

\begin{verbatim}
# Module-level function (picklable)
def _compute_matmul_block(A, B, start, end):
    return start, end, A[start:end, :] @ B

class MultiProcessOperations:
    def matrix_multiply_multiprocess(self, A, B):
        with ProcessPoolExecutor() as executor:
            executor.submit(_compute_matmul_block, A, B, ...)
\end{verbatim}

\subsection{Dask Cluster Management}

Dask clusters must be explicitly shut down to avoid port conflicts:

\begin{verbatim}
try:
    cluster = LocalCluster(n_workers=4)
    client = Client(cluster)
    # ... benchmark operations ...
finally:
    client.close()
    cluster.close()
\end{verbatim}

Without the \texttt{finally} block, failed runs leave zombie processes holding ports 8786-8787, causing subsequent runs to fail.

\subsection{Error Handling in Benchmark Loop}

Distributed operations can fail transiently. The benchmark harness catches exceptions and continues:

\begin{verbatim}
try:
    dist_ops.setup_cluster()
    stats = harness.run_repeated_benchmark(...)
    summary_stats.append(stats)
except Exception as e:
    print(f"Warning: Distributed ops failed: {e}")
    print("Continuing with remaining benchmarks...")
finally:
    dist_ops.shutdown_cluster()
\end{verbatim}

This ensures partial results are saved even if some configurations fail.

\section{Testing Implementation}

\subsection{Correctness Tests}

Matrix operations are validated against NumPy's reference implementations:

\begin{verbatim}
def test_matrix_multiply_threaded():
    ops = MultiThreadedOperations(size=100, n_threads=4)
    A, B = ops.generate_matrix(), ops.generate_matrix()
    C_threaded = ops.matrix_multiply_threaded(A, B)
    C_numpy = A @ B
    assert np.allclose(C_threaded, C_numpy, rtol=1e-5)
\end{verbatim}

\subsection{Dask Integration Tests}

Distributed tests require cluster setup/teardown:

\begin{verbatim}
@pytest.mark.timeout(60)  # Prevent hangs
def test_matrix_multiply_distributed():
    ops = DistributedOperations(size=100, n_workers=2)
    try:
        ops.setup_cluster()
        A, B = ops.generate_matrix(), ops.generate_matrix()
        C_dask = ops.matrix_multiply_distributed(A, B)
        C_numpy = A @ B
        assert np.allclose(C_dask, C_numpy, rtol=1e-5)
    finally:
        ops.shutdown_cluster()
\end{verbatim}

The \texttt{@pytest.mark.timeout} decorator prevents indefinite hangs if cluster initialization fails.

\section{Performance Optimizations}

\subsection{Matrix Generation}

Matrices are generated once per size and reused across iterations, avoiding redundant computation:

\begin{verbatim}
for size in matrix_sizes:
    # Generate once
    A = np.random.rand(size, size)
    B = np.random.rand(size, size)
    
    # Reuse across all configurations
    for n_workers in worker_counts:
        for iteration in range(5):
            ops.matrix_multiply(A, B)  # Same A, B
\end{verbatim}

\subsection{Monitoring Interval Tuning}

Memory and CPU monitors sample at 50ms and 100ms respectively. Finer intervals (<10ms) introduce measurable overhead; coarser intervals (>500ms) miss transient peaks. Empirical testing established these values as optimal trade-offs.

\section{Lessons Learned}

\subsection{Dask Port Conflicts}

Early runs failed due to zombie Dask processes holding port 8787. Solution: always use \texttt{try/finally} for cluster lifecycle management.

\subsection{GIL and Threading}

Initial threading tests showed no speedup. Root cause: NumPy was using internal multithreading, creating nested parallelism and GIL contention. Solution: Disable NumPy threading via environment variables.

\subsection{Multiprocessing Overhead}

Multiprocessing showed 10-15ms startup overhead even for tiny matrices. This is process forking cost. Solution: Document clearly that multiprocessing is only beneficial for larger workloads.

\section{Summary}

The implementation prioritizes correctness, reproducibility, and maintainability for the local harness plus a partial live EC2 round-1. Completed multi-instance \texttt{da.matmul} remains the residual.

\section{Related Work}

\subsection{Architectural Foundations of Distributed Message Queuing}
The foundational literature on message queuing in distributed systems, particularly the work of \cite{tanenbaum2023} and \cite{coulouris2022}, defines the core challenges of asynchronous communication: message ordering, delivery guarantees, and fault tolerance. In serverless and cloud-native architectures, these challenges are exacerbated by the ephemeral nature of compute resources and the loss of traditional stateful server management. This section surveys how Amazon Simple Queue Service (SQS) addresses these challenges within AWS, and critiques current academic and industrial approaches to reliability.

\subsection{At-Least-Once Delivery Paradigms}
Amazon SQS provides "At-Least-Once" delivery guarantees, a standard pattern for high-availability systems (\cite{amazon2025}). Literature from 2020–2026 (\cite{kyrychenko2025}) underscores that overcoming this semantic constraint is the primary challenge for the developer. The fundamental architectural pattern for reliable distributed state mutation involves idempotency keys stored in stateful backend services like DynamoDB or Redis, with TTLs to manage storage overhead. \cite{li2024} demonstrates that failure to implement robust idempotency leads to state corruption under retry scenarios exceeding a 2\% event failure rate.

\subsection{Dead Letter Queues (DLQ) and Redrive Strategies}
As highlighted in \cite{sqs-reliability-2025}, the maturation of Dead Letter Queue (DLQ) redrive mechanisms has dramatically simplified asynchronous recovery. Older patterns necessitated the construction of secondary worker functions dedicated strictly to message reconciliation. Current research suggests that native AWS Source Queue Redrive policies, combined with automated alerting on queue depth anomalies, are sufficient to handle 95\% of "poison pill" scenarios.

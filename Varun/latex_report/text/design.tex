\chapter{Design}

The artefact is organised as a four-stage pipeline over synthetic (or, in a future live
campaign, inventory-derived) object metadata:

\begin{enumerate}
    \item \textbf{Workload / metadata.} Local simulator emits object features (size, age,
          access frequency/recency) under \texttt{DRY\_RUN=1}. A live Boto3 Inventory
          collector is \textbf{not} present on disk.
    \item \textbf{Recommendation.} TierBase-inspired rules (\texttt{recommendation/baseline.py})
          and an XGBoost classifier (\texttt{recommendation/ml\_recommender.py}) map features
          to an S3 storage class.
    \item \textbf{Forecasting.} Prophet is compared to naive persistence (Beck et al.) on a
          temporal holdout of synthetic daily storage cost.
    \item \textbf{Savings.} Delta pricing against local \texttt{configs/pricing.json} estimates
          monthly \$ impact versus unoptimized / lifecycle / Intelligent-Tiering baselines.
\end{enumerate}

Design constraints for CA2 honesty: every claimed metric must resolve to a committed JSON
field; live AWS services are scaffolds only (\texttt{terraform/}, undeployed).
